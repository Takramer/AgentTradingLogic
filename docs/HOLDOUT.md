# Holdout reservation

**Established:** 2026-07-24 · **Authority:** docs/AUDIT-2026-07-24.md §8 Phase 0

This file is the record of which data may be used for development and which may
not. It is append-only. Do not edit a past entry; add a new one.

---

## The uncomfortable fact first

**There is no clean holdout in this project today.**

The cached history runs 2024-07-18 → 2026-07-20. Every artifact in
`tests/results/` was generated over some slice of it, and the config decisions
recorded in `config.json` (ETF exclusion, ADR exclusion, biotech exclusion,
`min_stop_pct`, `winsor_r_cap`, `legMask`, PEAD on/off) were each made by
observing full-sample results across that same span. `sanity.py`'s
`is_oos_split` check reports the last 30% of the window as "OOS"; that window
has been viewed during every one of those decisions.

Reserving a window *now*, after it has been seen, does not make it out-of-sample.
It makes it **quarantined** — better than nothing, and much worse than clean.

Both windows below are therefore defined, with different evidentiary weight.

---

## W1 — DEVELOPMENT (unrestricted)

```
2024-07-18  →  2025-12-31        (~365 cached sessions)
```

All fitting, tuning, sleeve selection, universe rules, ablation, threshold
sweeps and exploratory work happen here. Look at it as much as you like.

Note this window is *longer* than the one that produced the headline
`+6,577R` artifact, which only covered 2025-09-11 → 2026-07-17 (213 signal
days). Re-running development work on W1 is a strict improvement in sample size
and adds a genuinely different regime.

## W2 — QUARANTINED (already viewed; use once, discount heavily)

```
2026-01-01  →  2026-07-20        (~135 cached sessions)
```

**Status: contaminated.** Use it exactly once, as a *consistency check* after
W1 development is frozen. A pass here is weak evidence. A failure here is strong
evidence — a strategy that cannot reproduce on data it was implicitly fitted to
is dead.

Never quote W2 results as out-of-sample performance. Never tune against them.

## W3 — TRUE HOLDOUT (forward only; the only clean evidence available)

```
2026-07-21  →  onward            (accumulates from today)
```

The only data in this project that has never influenced a decision is data that
did not exist when the decisions were made. W3 is the real holdout and it grows
one session per day.

**Gate: no promotion to paper trading until W3 contains ≥ 125 sessions
(~6 months) of results generated by a config frozen before 2026-07-24.**

This is the honest cost of the audit findings: the credible evaluation of this
system starts now and takes about six months. Shortening that means going live
on evidence that does not exist.

---

## Rules

1. Any run touching W2 or W3 must be logged below **before** it is executed,
   with the config hash it will use.
2. A config change after a W2/W3 look resets that window's evidentiary value to
   zero for the new config. There is no partial credit.
3. `--date-hi 2026-01-01` is the default guard for development runs. Do not
   remove it without an entry here.
4. W3 results are only valid for a config committed and hashed *before* the
   sessions in question occurred. Retroactive claims are not admissible.
